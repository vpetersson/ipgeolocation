An address
becomes a place.

A self-hosted IP geolocation and timezone API. The MaxMind GeoLite2 database and the timezone boundaries ship inside the container, so a lookup is a local read rather than a call to somebody else's service.

The API

Two shapes. The short one keeps a small, stable payload; the /v1 one adds currency, calling code, flags and the rest. 

# The caller's own address, detected from proxy headers
GET /

# A specific address, short shape
GET /ipgeo?ip=8.8.8.8

# A specific address, full shape
GET /v1/ipgeo?ip=8.8.8.8

# Coordinates to timezone. Note the parameter is `long`, not `lon`.
GET /timezone?lat=51.5074&long=-0.1278
→ {"timezone":"Europe/London"}

The service also publishes /openapi.yaml and /llms.txt, so it is describable to both a code generator and an agent without anyone writing a client by hand.

Run your own

The image carries its own data, so there is no API key to obtain and no account to create. 

docker run -p 3000:3000 ghcr.io/vpetersson/ipgeolocation:latest

# then
curl "http://localhost:3000/ipgeo?ip=1.1.1.1"

  1. Start the container

    One process, one port, no external dependencies to wire up first.

  2. Put it behind your proxy

    It reads CF-Connecting-IP, X-Real-IP and X-Forwarded-For, so GET / answers for the real caller.

  3. Let the cache work

    An in-memory LRU sits in front of the database, and responses carry Cache-Control so a proxy can hold them too.

Why run it yourself

The addresses stay with you

A hosted geolocation API sees every IP you look up, which for most applications means every visitor you have. This one sees nothing, because it is yours.

No rate limit, no key

The data is in the image. Lookups cost a memory read, so there is no quota to budget or key to rotate.

Predictable latency

Nothing in the request path crosses the internet, so a lookup does not inherit somebody else's outage or slow day.

Timezones from geometry

Coordinates resolve against real timezone boundaries with tzf-rs, rather than being guessed from a country.

Protobuf when you want it

Ask for protobuf instead of JSON where the payload size matters.

Published with an SBOM

Each release publishes a software bill of materials, so what is inside the image is a matter of record.
